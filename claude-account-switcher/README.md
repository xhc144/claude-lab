# Windows Claude 桌面版账号切换器（可试用版）

适用对象是官方 **Claude Desktop 桌面客户端**，包括其本地配置和浏览器登录状态。
当前在这台电脑安装的 Claude MSIX 4.29.0 上做了静态研究和空配置运行验证。

## 使用前先知道

程序已实现完整数据目录切换和失败恢复。账号首次必须在官方 Claude 窗口登录；授权仍有效时，后续切换复用该账号保存的状态。

**真实双账号的登录复用尚未验收。** 已做的运行验证使用空配置，现有真实账号没有被移走，也没有替用户登录第二个账号。先按下面步骤完成首次配置，再验证两次往返。

切换前须从 Claude 托盘菜单选择 **Exit／退出**，让整个桌面客户端完全退出。点击窗口右上角 × 通常只是隐藏窗口。程序检查到桌面进程仍在运行时会停止操作，不强制结束任务。

## 首次配置

1. 正常打开官方 Claude，确认当前账号正常。随后从托盘完全退出。这样也让客户端先完成自己的更新和数据迁移。
2. 双击桌面“Claude 桌面账号切换器”，点击 **保留原有账号**。这一步登记当前目录，保留原来的登录。
3. 点击 **新增账号**，输入名称，例如“账号 B”。
4. 选择“账号 B”，点击 **切换并打开**。此时原账号完整数据移入私人账号库，官方客户端以新的空配置启动。
5. 在官方窗口完成 B 的首次登录。请使用你自己的登录方式；程序不收集密码和验证码。
6. 完全退出 Claude，回到切换器选择“原有账号”，点击 **切换并打开**。
7. 确认原账号仍保持登录，再退出并切回 B，确认 B 也保持登录。这是首次双账号验收。

## 日常切换

完全退出 Claude → 在切换器选择目标账号 → 点击“切换并打开”。无需主动点击 Claude 的“退出登录”。

每个账号的桌面配置、本地会话、扩展设置随各自的数据目录保存。新增账号需要做自己的首次设置。

## 数据在哪里

程序文件可以放在桌面；账号资料保存在：

`C:\Users\37542\.claude-desktop-switcher`

当前账号的数据始终位于 Claude 原生目录，当前电脑检测到的是：

`C:\Users\37542\AppData\Roaming\Claude`

其他账号放在私人账号库的 `stored/<账号标识>/data` 中。**账号库包含实际登录状态和本地资料，请保留它，不要当缓存清理，也不要发给别人。**

想恢复最初状态，先完全退出 Claude，再在切换器中打开“原有账号”。之后可以删除桌面程序入口；其他账号资料仍留在账号库里。

## 出现问题时

- 提示仍在运行：从 Claude 托盘选择 Exit／退出后重试。
- 提示未完成的切换：保留现场，完全退出 Claude，点击 **恢复上次操作**。
- 提示数据目录迁移或多个数据目录：程序会停止，避免移动错误目录。保留账号库和原目录，先核对更新后的实际位置；不要反复重新初始化。
- 已切换但启动失败：登录资料仍在，修复客户端安装后重试打开所选账号。
- 官方要求重新认证：授权可能已经失效或被撤销，需在该账号的官方窗口重新登录。

## 技术实现与验证

客户端的首次浏览器登录通过全局 `claude:` 协议返回；单纯用不同 `--user-data-dir` 启动，可能把登录回调送错实例。因此正常入口保持官方默认启动路径，在完全退出后用同卷目录重命名切换完整资料。

切换保存最新的完整状态，包括 Windows 加密相关文件、Cookie 数据库和本地存储；没有复制过期令牌副本。程序不解密令牌、不调用服务端退出登录，也不改系统的协议关联。

目录操作有跨进程锁、落盘事务记录、原子清单更新和目录身份校验。失败时尝试恢复；状态不明确时停止并保留现场。只移动确认过的目录，不递归删除账号资料。

已通过 32 项隔离自动测试：账号往返、最新状态保存、两阶段崩溃、提交后恢复、失败回滚、运行进程阻止、重复操作锁、目录替换冲突、错误目录拒绝及迁移保护。

真实 Claude 4.29.0 空配置验证：新目录可启动客户端；两份完整配置往返后关键文件哈希一致；原有真实账号的 config.json 和 Local State 哈希未变。

真实双账号授权、Google／邮件／SSO 登录以及 Code／Cowork 的实际任务续用，仍需首次配置后验收。客户端以后更新了存储方式，也可能需要重新适配。

源码研究记录和原始分析证据保留在 Documents/Codex 工作目录，未随桌面工具分发。REA 启动分析证据：`ev_35e346de2c7fa488bc82f543ac179a26585c929040e75f2bd6e367cf80a94210`。分析只选择了启动入口与 package.json，其他模块由普通静态工具作定向检查；它不是完整安全审计。

## 命令行与测试

在程序目录运行：

```powershell
python desktop_accounts.py doctor
python desktop_accounts.py init
python desktop_accounts.py add "账号 B"
python desktop_accounts.py list
python desktop_accounts.py open <账号标识>
python desktop_accounts.py recover
python -m unittest tests_desktop_service tests_profile_switcher -v
```

正常桌面入口使用 `desktop_accounts.py`。`account_manager.py` 在此项目中主要提供系统安装、进程检查和目录权限辅助；其独立目录实验入口不用于正式切换流程。
